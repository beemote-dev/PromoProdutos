## Por que não capturava

- O histórico anterior do repositório registrava Magalu HTTP 403, ML HTTP 200 sem
  preço confiável (40.620 bytes) e Amazon HTTP 200 sem preço confiável
  (1.569.761 bytes). Esses HTMLs antigos não estão versionados: não é possível
  afirmar se eram desafios, páginas parciais ou produtos sem oferta. Não se deve
  tratar o código 200 como prova de acesso ao produto.
- **Magalu:** nesta execução o bloqueio não se repetiu. O JSON-LD também continha
  `1029.99`; o parser anterior provavelmente o encontraria nesta resposta. Logo,
  não há evidência de que a indisponibilidade anterior fosse causada apenas por
  seletor incorreto. O método adotado usa o estado público `__NEXT_DATA__`, pois
  ele comprova explicitamente produto, vendedor, moeda e Pix. O total parcelado
  era R$ 1.287,49 e a parcela R$ 128,75; nenhum deles é o preço à vista.
- **Mercado Livre:** a URL usa o produto de catálogo `MLB63741571`. O código
  consultava, quando havia token, o anúncio fixo `MLB4480279587` sem validar sua
  relação com esse catálogo. Isso podia associar um preço incorreto ao Dako.
  A página real foi negada, inclusive no navegador.
- **Amazon:** a heurística de procurar `a-offscreen` até 12.000 caracteres depois
  de um marcador não respeitava o fechamento do bloco e podia alcançar outras
  ofertas. Não houve captura real bem-sucedida para justificar esse método.
  Nesta execução o servidor recusou o cliente; executar JavaScript não resolveu.
- Metadados genéricos e JSON-LD sem confirmação de identidade, vendedor e condição
  de pagamento não demonstram o preço à vista pretendido.

## APIs oficiais

- **Mercado Livre:** Go testou, sem token, `GET
  https://api.mercadolibre.com/products/MLB63741571`,
  `/products/MLB63741571/items` e, somente para diagnosticar o código antigo,
  `/items/MLB4480279587/prices`. Todos responderam HTTP 403 com página HTML de
  erro, não um preço JSON. O ambiente não disponibiliza credenciais: não foi
  validada uma chamada autenticada nem foi possível confirmar o anúncio fixo.
  A [documentação oficial](https://developers.mercadolivre.com.br/pt_br/itens-e-buscas)
  apresenta chamadas com Bearer token. Não se infere que apenas adicionar token
  resolverá o acesso ou confirmará preço à vista. A consulta fixa foi removida;
  o secret existente no workflow foi preservado para eventual integração futura.
- **Amazon:** a [Creators API](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/introduction)
  exige inscrição no programa de associados, habilitação e credenciais. Nenhuma
  dessas credenciais estava disponível no ambiente. A documentação de
  [migração](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/migrating-to-creatorsapi-from-paapi)
  identifica o serviço atual; não foi adicionada uma implementação especulativa
  da antiga PA-API nem uma chamada autenticada sem credenciais.
- **Magalu:** as [APIs de portfólio](https://developers.magalu.com/docs/apis/products/overview/index.html)
  exigem escopos de seller para preço e produto. Não havia credenciais desse
  vendedor. O `__NEXT_DATA__` usado é o JSON público da própria página, **não**
  uma API oficial de preços. Não foram chamados endpoints internos de GraphQL.

## Implementação e regressões

Somente o extrator de Pix do Magalu está habilitado. Exige `data.item.id` e
`variationId` iguais ao ID da URL, produto disponível, exatamente uma oferta do
`seller_id` configurado, vendedor ativo/disponível, moeda BRL e
`bestPrice.paymentMethodId == "pix"`. Recomendações, fallback, preço de tabela,
parcelas e metadados genéricos não são usados. Valores inválidos e ofertas
ambíguas falham sem retornar preço. Nenhum valor observado é constante no coletor.

Amazon e ML continuam recebendo uma requisição de diagnóstico; sem sucesso
comprovado, retornam indisponível mesmo se uma resposta 200 contiver algum preço.
O diagnóstico distingue CAPTCHA, autenticação/login, negação de acesso, limite de
requisições, erro remoto e ausência de método validado. Não há retentativas para
superar bloqueios nem fallback para outro vendedor, produto ou loja.

O workflow `.github/workflows/monitor.yml`, seu agendamento, secrets, permissões e
publicação do histórico estão intactos. A função de envio e as regras de alerta
do Telegram foram preservadas. Os testes simulam o transporte HTTP: **não enviam
mensagens reais**. A interface indica quando o valor é no Pix.

Os testes abrangem a fixture reduzida da resposta real, seleção de preço,
rejeição de produto/vendedor/variante/moeda divergentes, indisponibilidade,
parcelamento, valores inválidos, ofertas duplicadas, recomendações, JSON bruto,
403/503, CAPTCHA em HTTP 200, redirecionamentos, limites de corpo, falha de rede,
lojas sem método validado, persistência diária, cópia para Pages e Telegram.

Validação concluída: `go test -race -cover ./...` passou (90,2% de cobertura no
monitor), `go vet ./...` e `git diff --check` passaram. O painel também foi
verificado com Playwright: três cards, Philco com indicação de Pix e os outros
dois indisponíveis com seus diagnósticos. O gráfico externo não participou dessa
verificação de interface. O workflow foi comparado byte a byte com a versão base.

## Reproduzir

Na raiz do repositório, com Go 1.23+:

```sh
go test -race -cover ./...
go vet ./...
go run ./scripts/probe.go -output work/probes
# Atualiza o histórico; alvos/credenciais podem habilitar alertas reais:
go run ./cmd/monitor
```

Para os probes de navegador, instale Playwright Python e um Chromium compatível:

```sh
python scripts/probe_pages.py --chromium /usr/bin/chromium --output work/probes
```

Playwright é apenas uma ferramenta de investigação e não é dependência do monitor
ou do Actions. O script visita uma vez cada URL, aguarda 5 segundos, salva HTML,
texto, screenshot e status; não interage com desafios. `HTTPS_PROXY`, quando
fornecido pelo ambiente, é respeitado. Não use `ignore_https_errors`: a CA do
proxy precisa estar no armazenamento confiável do navegador. Os primeiros testes
tiveram `ERR_CERT_AUTHORITY_INVALID`; após importar a CA fornecida pelo ambiente
ao NSS na mesma sessão de execução, as três páginas foram testadas com TLS ativo.

As fixtures em `cmd/monitor/testdata` são evidências de teste, não fontes de preço
em produção. Os arquivos brutos de probes ficam em `work/`, ignorado pelo Git;
não publique cookies, tokens ou dados de sessão. A fixture Magalu conserva apenas
o estado de item/oferta necessário e o preço visível; as páginas pequenas de
bloqueio ML/Amazon são as respostas reais do probe Go.
